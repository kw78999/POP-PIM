# RTL entry points

| Path | Top | Checked by |
|---|---|---|
| `dense/dense_score_port16.sv` | Dense scorer with 16-byte Q/K ports (D1–D32) | `tools.calibrate_dense`, `tools.synthesize_dense` |
| `scoring/score7_top.sv` | Two-context popcount BF16 scorer | `tools.calibrate_pop` |
| `gqa/gqa4_frontend.sv` | GQA4 metadata ownership, allocation and score routing | `tools.build` (live in the simulator) |
| `bank/gqa4_score_bank.sv` | Scorer + query mux + GQA4 frontend: one POP score bank | `tools.synthesize_pop` |
| `bank/gqa4_score_bank_gs.sv` | The same bank with the GS unit between scorer and router | `tools.synthesize_extensions` |
| `gs/gs_shared_score.sv` | GS unit: `((s0+s1)+(s2+s3))×0.25` per KV head, BF16 RNE; includes the exact ×0.25 unit | `tools.verify_rtl` (gs, quarter) |
| `vs/vs_mass_threshold.sv` | VS engine per KV head: logit binning, mass histogram, threshold scan, keep query | `tools.verify_rtl` (vs) |
| `transport/score_stream_interface.sv`, `score_stream_interface_w.sv` | S-path output staging, 64-bit tagged packets and width-parameterized (16-bit CT packets) | `tools.synthesize_extensions` |
| `refresh/pim_refresh_sched.sv` | Per-bank (REFsb) refresh decision logic of the simulator's `per-bank` policy | `tools.verify_rtl` (refresh) |
| `selector/` | Earlier exact-selection prototypes | Unit tests only |

`vs/vs_tables.svh` and `vs/vs_tables.json` are generated by `vs/gen_vs_tables.py` (fixed-point exponent tables and
bin weights). HardFloat sources and their license are under `third_party/hardfloat/`. The system evaluation uses the
cycle model in `simulator/common/selector_cluster_sram.h` for the L-path selector; no complete selector cluster is
claimed as synthesized. See [the architecture guide](../docs/architecture.md).
